# Incident reports

Record injuries, illnesses, behavioural incidents and serious occurrences, route them for review, and get parents to acknowledge — with a full audit trail. Sidebar → **Incidents**.

## Who does what

- **Educators** file a report (**+ New report**), saving as a **draft** or **submitting** it for review.
- **Directors / admins** review submitted reports, notify the parents, and close them out.
- **Parents** see a report only after it's shared with them, and **acknowledge** it with a typed signature.

## The workflow

A report moves through these states:

1. **Draft** — the educator is still writing it.
2. **Awaiting review** — submitted to the director.
3. **Reviewed** — the director has read it (they can add director notes here).
4. **Awaiting parent** — shared with the child's parents (push + email).
5. **Acknowledged** — a parent has signed it.
6. **Closed** — the director closes it out.

Serious occurrences (CCEYA) are flagged automatically and badged **SO**.

## Opening a report

The Incidents list shows When / Child / Type / Severity / Status / Recorded by, with a **⋮ menu** to **View** each one. On the detail page you'll always see a **← Back to incidents** button, so you can leave without having to close the incident.

## Notes & details (staff only)

Every incident has a **Notes & details** section where staff can add follow-up notes after the fact — a phone call to the parent, a corrective action, a witness who came forward. Each note records **who wrote it and when**, so the incident builds a complete, audit-trailed history. These notes are **internal**: parents never see them.

## Director actions

From an incident's detail page a director/admin can:

- **Mark reviewed** — with optional notes for the parent
- **Notify parent** — sends the report to the child's parents to acknowledge
- **Close** — once it's resolved
- **Add notes** at any time (see above)
